# AD-55: ORM MVP — decorator entities, data source, repository, entity and transaction managers

**Date:** 2026-03-30
**Status:** Accepted — implemented (MVP inline per plan); superseded in part
by [AD-30](2026-09-26_AD30_ORM_MIGRATIONS.md) /
[AD-31](2026-09-26_AD31_ORM_RELATION_FETCH.md) (2026-09-26) and
[AD-07](2026-09-05_AD07_ZOD_VALIDATION.md) (2026-09-05, validation from entity
metadata).

## Context

ndigo needed a Repository + Data Mapper persistence layer for `ndigo-demo`
without external database dependencies. The decision was a contracts-first
`@ndigo/orm` package: decorator-annotated entities, an isomorphic
(dependency-free) core, and an in-memory adapter usable immediately, with
real database adapters and validation deferred. Much of the deferred surface
later landed and superseded parts of the MVP — records kept here.

## Evidence

- Plan: `docs/plans/2026-03-30_ORM_MVP.md` — package structure, core API
  surface, dependency rules, deferred items, success criteria.
- `@ndigo/orm` persists today:
  `packages/ndigo-orm/src/{decorators,data-source,entity-manager,repository,transaction-manager,unit-of-work}.ts`,
  exported via `packages/ndigo-orm/src/index.ts` (types `DataSource`,
  `EntityManager`, `EntityState`/`UnitOfWork`, `TransactionManager`,
  `Repository`/`AsyncRepository`; classes `InMemoryDataSource`,
  `InMemoryEntityManager`, `InMemoryUnitOfWork`,
  `InMemoryTransactionManager`, `AbstractRepository`, `InMemoryRepository`).
- `@entity`/`@column`/`@primaryColumn`/`@generated` decorators write metadata
  into `Symbol.metadata` under `orm:`-prefixed keys (decorators.ts,
  `_constants.ts`).

## Decision

- **D-1 — platform: universal isomorphic core,** dependency-free, Layer 2
  (Infrastructure) alongside `@ndigo/factory`, `@ndigo/validate`; no
  `@ndigo/context` dependency.
- **D-2 — MVP scope: contracts + in-memory adapter** so `ndigo-demo` can use
  it immediately with no external deps.
- **D-3 — wrap-vs-build: pure contracts for MVP, wrap adapters later**
  (keeps core dependency-free; `@ndigo/orm-drizzle` becomes the integration
  adapter).
- **D-4 — pattern: Repository + Data Mapper** (aligned with the Java data-mapper tradition, fits
  the existing DI/IoC via `@ndigo/factory` `Initializable`/`Destroyable` and
  the `ApplicationContextAwareProcessor` calling `init()`/`destroy()`).
- **D-5 — surface (camelCase per STYLE_GUIDE):** decorators `@entity`,
  `@primaryColumn`, `@column`, `@generated`; interfaces `DataSource`,
  `EntityManager` (persist/find/findAll/remove/flush), `Repository<T, ID>`
  (save/findById/findAll/deleteById/count), `UnitOfWork`
  (new/dirty/removed + flush); in-memory implementations of each.
- **Deferred to post-MVP:** relation decorators (`@oneToMany` etc.), query
  builder, lifecycle hooks, `@transactional`, migrations, real adapters
  (`@ndigo/orm-drizzle`), `@ndigo/validate` integration.

## Supersession (in part)

- Relations, populated in the MVP's deferred list, landed 2026-09-26:
  [AD-31](2026-09-26_AD31_ORM_RELATION_FETCH.md) (explicit join-column
  metadata + opt-in loading).
- Migrations, also deferred, landed 2026-09-26:
  [AD-30](2026-09-26_AD30_ORM_MIGRATIONS.md) (journaled versioned DDL in
  `@ndigo/orm-drizzle`).
- Validation: AD-07 (2026-09-05) replaced the planned `@ndigo/validate`
  integration; `ndigo-orm` entities keep decorator annotations but validation
  is derived from them via a per-entity Zod schema
  (`packages/ndigo-orm/src/entity-schema.ts`), and the legacy `entity.validate()`
  hook was dropped.

## Consequences

- `@ndigo/orm` built out decorator metadata + in-memory store first; real
  adapters came later as `@ndigo/orm-drizzle` (an integration layer that
  imports Drizzle directly).
- The MVP's transaction concept (UnitOfWork state-tracking) persists
  alongside a dedicated `TransactionManager`
  (`InMemoryTransactionManager`), and `@transactional` now exists.
- Validation now derives from entity metadata + Zod (AD-07) rather than the
  planned `@ndigo/validate` decorators.
