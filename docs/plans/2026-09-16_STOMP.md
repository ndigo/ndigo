# 2026-09-16 STOMP Protocol Layer

**Status:** Implemented in two waves (ratified by [AD-23](../decisions/2026-09-16_AD23_STOMP.md);
first wave shipped in the 2026-09-16 AD-23 session: codec, broker, client,
`@stompMapping`, adapter subprotocol negotiation, blue-api demo gate).
Second wave (D7–D11) closes the original deferrals: per-session
transactions, ack tracking + NACK redelivery, byte-exact binary frames,
`/user` scoped routing, `/queue` bounded store-and-forward.
**As-built deviations (surface changed after this plan was written):**

- Subprotocol selection is hard-wired per path in the adapter (stomp-mapped
  path → best mutual STOMP protocol; other paths → first offered, stock ws
  behavior). No user hook option.
- Client `ack`/`nack` live on `StompSubscription` only (no client-level
  `#ack(none)` method); ACK/NACK frames are never queued — they are only
  valid while connected and drop otherwise (they would race ahead of
  CONNECT on a reconnect).
- Client `send()` always attaches a fresh `receipt` header and resolves on
  RECEIPT; a caller-supplied `receipt` header is honored.
- Subscription lifecycle uses a per-entry `pending | live` state (the
  plan's "re-subscribe active subscriptions" pass), driven by the socket's
  status signal (`effect`), so CONNECTED flips cannot double-SUBSCRIBE.
  **Scope:** `@blue/socket` (codec, server broker, client — all isomorphic),
  `blue-dispatcher` (`@stompMapping` marker), `blue-platform-node`
  (subprotocol negotiation), `apps/blue-api` (demo gate)
  **Companion docs:** [AD-23](../decisions/2026-09-16_AD23_STOMP.md),
  [Framework Gap Analysis](../audits/2026-09-13_FRAMEWORK_GAP_ANALYSIS.md) §2.3 (WebSockets row,
  "STOMP/SockJS" deferral), [AD-21](../decisions/2026-09-15_AD21_WEBSOCKET_SESSION_REGISTRY.md),
  [AD-22](../decisions/2026-09-15_AD22_WEBSOCKET_CLIENT.md)

## 1. Problem

The gap analysis records WebSockets as present-but-incomplete with
"no STOMP". AD-22 D5 explicitly reserved STOMP as the next socket-domain
layer, post-client:

> STOMP (destinations, subscriptions, frames) is a real future feature,
> scheduled after the client lands: client frame codec in `@blue/socket`,
> server-side in `blue-platform-node` (or a socket-server sibling).

Concretely, BlueJS today has rooms + broadcast (AD-21) and a reconnect
client (AD-22), but no **broker protocol over the socket**: no destinations,
no subscription frames, no ack modes, no receipts, no interop with the
industry-standard STOMP wire (Spring `SimpMessagingTemplate`, RabbitMQ
STOMP plugin, ActiveMQ Artemis, @stomp/stompjs clients). A BlueJS app
cannot be addressed by a STOMP client, and a BlueJS client cannot speak to
a STOMP broker.

Scope decision (from the 2026-09-16 assessment): STOMP **1.2 core** —
CONNECT/CONNECTED negotiation, SEND, SUBSCRIBE/UNSUBSCRIBE, MESSAGE,
ACK/NACK, receipts, heart-beat negotiation (answered `0,0`; the WS layer
owns liveness). Transactions (BEGIN/COMMIT/ABORT) are answered with ERROR,
and STOMP-over-TCP is out of scope — WebSocket only (browsers, STOMP.js,
and Spring all use the WS variant; there is no consumer base for a raw TCP
listener).

## 2. Current state (verified 2026-09-16)

- `@blue/socket` (AD-22): `SocketSession` (path/params/sources, async
  iterable `messages`, `send`/`close`/`join`/`leave`, `attributes`),
  `SocketSessionRegistry` (rooms, broadcast, backpressure), `SocketClient`
    - `WebSocketClient` (status signal, reconnect, online trigger seam),
      `AsyncReader`. Package deps: `@blue/signals` only. This is the
      isomorphic socket domain — the natural home for a protocol layer.
- `blue-dispatcher`: `@socketMapping` (route + `route:socket:<method>`
  metadata marker), `isSocketMapping()`, `socketSession()` extractor;
  re-exports the moved socket contracts from `@blue/socket` (AD-22 D2).
- `blue-platform-node`: `NodeHTTPServerAdapter` builds `WebSocketServer`
  (from `ws`) with `shouldHandle`/`verifyClient`/`connection` wiring.
  `ws` supports `handleProtocols(protocols: Set<string>, req)` — called
  during `completeUpgrade` after `Sec-WebSocket-Protocol` parsing; a
  falsy return omits the response header (no handshake abort). Default
  without the hook: the **first** offered protocol is echoed.
- Dispatch shape: socket handlers may be broadcast-style async functions
  consuming `session.messages` (`#dispatchSocket` awaits their promise) —
  exactly the loop a STOMP endpoint needs; no adapter dispatch changes.

## 3. Architecture (AD-23)

STOMP is a **protocol layer over the socket contracts**, so all protocol
machinery is isomorphic and lives in `@blue/socket`; the platform only
gains subprotocol negotiation glue:

| Piece                                                         | Home                                   | Notes                                                                                                                                                                                                                                      |
| ------------------------------------------------------------- | -------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Frame codec (`parseStompFrame`/`serializeStompFrame`, errors) | `@blue/socket/src/stomp-frame.ts`      | Pure text; header escaping (STOMP 1.2 `\n`/`\r`/`\c`/`\\`), NUL termination, `content-length` handling                                                                                                                                     |
| Server broker (`StompBroker`)                                 | `@blue/socket/src/stomp-broker.ts`     | Subscription table per broker; `handleSocket(session)` runs the endpoint state machine over any `SocketSession`; `publish(destination, body, headers?)` for server-initiated fan-out; receipts; ack-mode accept/validate; `onMessage` seam |
| Client (`StompClient`)                                        | `@blue/socket/src/stomp-client.ts`     | `StompClient` wrapping a `SocketClient`; CONNECT negotiation, per-destination subscriptions as async iterables, receipts, ack, lifecycle mapping onto the socket status signal; auto re-CONNECT + re-SUBSCRIBE on `open`                   |
| `@stompMapping` decorator + `isStompMapping()`                | `blue-dispatcher/src/stomp-mapping.ts` | Mirror of `socket-mapping.ts` (`route:stomp:<method>` + route mapping); the adapter's opt-in signal for protocol negotiation                                                                                                               |
| Subprotocol negotiation                                       | `blue-platform-node` adapter           | `handleProtocols` selects `v12.stomp` (then v11, v10) when the upgrade path is stomp-mapped; non-stomp paths keep today's first-offered default exactly                                                                                    |
| Heart-beat                                                    | negotiated off                         | CONNECTED answers `heart-beat: 0,0` — the AD-21 registry ping/pong already covers liveness at the WS layer; STOMP-level beats would duplicate it                                                                                           |
| Broker lifecycle                                              | application bean                       | An app constructs `StompBroker` (bean, e.g. in `NodeAppConfiguration`) and hands it to a `@stompMapping` handler — mirror of `ChatController` + registry (AD-21 D4 composition)                                                            |

### Wire decisions

- **Frames are text.** `SocketSession.send`/`SocketClient.send` already
  send strings as text frames; STOMP-over-WebSocket is text (STOMP.js,
  Spring). Binary bodies with `content-length` are parsed correctly when a
  transport delivers them as strings; sending binary bodies is out of
  scope (no consumer among STOMP JS clients for this wire).
- **Version negotiation.** Client CONNECT carries `accept-version: a,b,c`;
  server responds with the highest mutual version (we implement 1.2
  semantics, accept 1.0–1.2, reply `version: 1.2` when offered).
- **CONNECT required first.** A session whose first frame is not CONNECT
  (or STOMP alias) is closed `1002` (protocol error). CONNECTED carries
  `session:` (opaque per-connection id) + `server:` (BlueJS) +
  `heart-beat: 0,0`.
- **Destinations.** `SUBSCRIBE destination` creates a subscription id →
  destination binding for that session (dst→room N:1 is wrong: two
  subscriptions to the same destination on one session must stay
  distinct). Fan-out sends a MESSAGE frame **per subscription** with the
  subscriber's own `subscription` id and a fresh `message-id`
  (`crypto.randomUUID()` — isomorphic).
- **SEND routing.** Default: SEND to a destination publishes to its
  subscribers (including the sender when subscribed — room-echo parity).
  An optional broker `onMessage(destination, body, headers, session)`
  hook may intercept (return `false` to suppress the default fan-out;
  returning `undefined`/void keeps it) — the app-routing seam.
- **Acks.** Modes `auto | client | client-individual` accepted and
  validated against the known subscription set. No redelivery: the broker
  is an in-memory fan-out with no persistence, so NACK/redelivery would be
  theater; ACK/NACK frames are parsed for the wire contract. Documented.
- **Receipts.** Any frame carrying `receipt:` header is acknowledged with
  RECEIPT (`receipt-id`) after processing; ERROR replies carry the
  `receipt-id` when the offending frame asked for one.
- **ERROR + close.** Frame-level protocol failures (unparseable frame,
  unknown command, missing required header, duplicate subscription id,
  BEGIN/COMMIT/ABORT) → ERROR frame with `message` header, then close
  `1002`. Matches the repo's fail-closed posture.
- **Empty frames (heart-beat pings).** Ignored on parse (STOMP 1.2
  allows a lone newline as a heartbeat); we never send them.

## 4. Surface

### `@blue/socket`

```ts
// stomp-frame.ts — codec
interface StompFrame { command: string; headers: Record<string, string>; body: string }
class StompProtocolError extends Error { /* message + optional receiptId */ }
function parseStompFrame(frame: string): StompFrame;
function serializeStompFrame(frame: StompFrame, opts?: { contentLength?: boolean }): string;

// stomp-broker.ts — server
interface StompBrokerOptions {
    onMessage?: (destination: string, body: string, headers: Record<string, string>,
                 session: SocketSession) => unknown;   // false = suppress fan-out
    nextMessageId?: () => string;                       // tests; default crypto.randomUUID
}
class StompBroker {
    constructor(options?: StompBrokerOptions);
    handleSocket(session: SocketSession): Promise<void>;  // runs until the session closes
    publish(destination: string, body: string, headers?: Record<string, string>): void;
    closeAll(): void;                                     // DISCONNECT-ish + session close
    readonly subscriptions: number;                       // observability
}

// stomp-client.ts — client
interface StompClientOptions {
    acceptVersion?: string;            // default '1.2'
    host?: string;                     // CONNECT host header; default from socket URL
    login?: string; passcode?: string;
    heartBeat?: string;                // default '0,0'
    reconnect?: boolean;               // re-CONNECT + re-SUBSCRIBE on socket open; default true
}
interface StompSubscription<T = string> {
    readonly id: string; readonly destination: string;
    messages: AsyncIterable<StompMessage<T>>;
    ack(messageId: string): void; nack(messageId: string): void;
    unsubscribe(): void;                                  // sends UNSUBSCRIBE; completes the stream
}
interface StompMessage<T = string> { destination: string; messageId: string; subscription: string;
                                     headers: Record<string, string>; body: T; json(): unknown }
class StompClient {
    constructor(socket: SocketClient, options?: StompClientOptions);
    readonly connected: Signal<boolean>;                  // false while connecting/reconnecting
    readonly closed: AsyncIterable<void>;                 // deliberate close completes
    subscribe<T = string>(destination: string, opts?: { id?: string; ack?: 'auto'|'client'|'client-individual' }): StompSubscription<T>;
    send(destination: string, body: unknown, headers?: Record<string, string>): Promise<void>;
    ack(messageId: string, subscription: string): void;
    nack(messageId: string, subscription: string): void;
    disconnect(): void;                                   // DISCONNECT + socket.close()
    waitForReceipt?(...) // internal — receipts resolve `send` promises
}
```

### `blue-dispatcher`

`@stompMapping(route)` — method decorator: same metadata shape as
`@socketMapping` plus `route:stomp:<method>` marker; `isStompMapping()`.
Exported from the dispatcher index. `@stompMapping` implies the socket
mapping (it delegates to `socketMapping`).

### `blue-platform-node`

`NodeHTTPServerAdapter`: pass `handleProtocols` to the `WebSocketServer`.
Selection for the upgrade path (parsed from `req.url`, mirroring
`#shouldHandle`): when the path's handler `isStompMapping`, return the
highest supported STOMP subprotocol the client offered
(`v12.stomp` > `v11.stomp` > `v10.stomp`), else `undefined` (no header).
For non-stomp paths, return the first offered protocol — byte-for-byte
today's default behavior.

`ws` non-abort note: a falsy `handleProtocols` return only omits the
response header; it never aborts the handshake (verified
`websocket-server.js:400-417`).

## 5. Phases

### Phase 0 — Codec (`stomp-frame.ts` + `stomp-frame.spec.ts`)

- `parseStompFrame`: command/headers/body split on the first blank line,
  NUL-terminated body; STOMP 1.2 header escaping (`\\`→`\`, `\n`→LF,
  `\r`→CR, `\c`→`:`) on values; `content-length` honored when present
  (body = that many chars, remainder is not consumed); empty frames
  (heart-beat ping) → command `''`.
- `serializeStompFrame`: escaping in values, `content-length` header on
  request (default: emit when the body would be ambiguous — contains NUL
  or leading-whitespace asymmetry; simplest: always emit for non-empty
  bodies), trailing NUL.
- Errors: `StompProtocolError` on unterminated frame, empty command with
  headers, invalid `content-length`, newline in a header name.
- Tests: round-trip, escape round-trip for all four escapes, `\n`/`\r`
  inside values, content-length with embedded NUL, empty body, ping frame,
  malformed inputs (`missing NUL`, `negative content-length`,
  `header line without colon`).

### Phase 1 — Server broker (`stomp-broker.ts` + spec)

- `StompBroker` with per-session subscription state (id → destination,
  ack mode), destination → subscription index for fan-out.
- `handleSocket`: first-frame-CONNECT enforcement; CONNECTED reply
  (version/session/server/heart-beat); SUBSCRIBE (duplicate id → ERROR),
  UNSUBSCRIBE (unknown id → ERROR), SEND (destination required → fan-out
  via `onMessage` seam), ACK/NACK validated, RECEIPT emission, ERROR+close
  paths, empty-frame tolerance; removal of all session subscriptions on
  session end (finally).
- `publish`/`closeAll`.
- Tests with a fake `SocketSession` (AsyncReader-backed push/complete —
  same double style as the client spec): CONNECT handshake, subscribe +
  publish fan-out per-subscription ids, SEND fan-out (including sender
  when subscribed), onMessage suppression, receipts, duplicate sub id /
  unknown unsub id / missing destination errors, non-CONNECT-first close,
  session-close cleanup, `crypto.randomUUID` message-id uniqueness.

### Phase 2 — Dispatcher marker + adapter negotiation

- `blue-dispatcher/src/stomp-mapping.ts` + index export + spec
  (metadata shape mirrors socket-mapping).
- Adapter: `handleProtocols` wiring in `listen()`; `#isStompPath(path)`
  probe (reuses `#findSocketHandler` + `isStompMapping`); spec: raw `ws`
  client offering `v12.stomp` over a `@stompMapping` route observes the
  subprotocol; a plain `@socketMapping` route keeps first-offered echo;
  no offered protocols → no header.

### Phase 3 — Client (`stomp-client.ts` + spec)

- CONNECT on first open; `connected` signal flips on CONNECTED; messages
  routed to subscription streams by `subscription` header; receipts
  resolve `send()` promises (internal receipt-id map, timeout optional);
  deliberate `disconnect()` sends DISCONNECT then closes the socket;
  unexpected socket close with `reconnect: true` → re-CONNECT +
  re-SUBSCRIBE (same ids) on next `open`; subscription streams stay open
  across the gap.
- Unit transport double with async-iterable `messages` (existing
  `socket-client.spec.ts` double style); assertions for the wire: CONNECT
  frame contents (accept-version/host/login/heart-beat), SUBSCRIBE id
  reuse on reconnect, MESSAGE → json(), ACK/NACK frames.

### Phase 4 — Demo gate (apps/blue-api)

- `StompChatController`: `@stompMapping('/stomp/chat')` + injected
  `StompBroker` bean (`NodeAppConfiguration` `@entry`), scheduler tick
  `publish('/topic/chat', …)` every 2s (scheduler → broker reachability,
  AD-20/AD-21 parity).
- e2e `stomp.spec.ts`: two `StompClient`s over `WebSocketClient` against
  the real app; subscribe both, one sends, both receive MESSAGE frames;
  receipts resolve; scheduler tick arrives; deliberate disconnect
  completes streams; `v12.stomp` subprotocol negotiated (assert via
  `ws` server-side telemetry-free path — client status suffices for the
  demo; negotiation has its own Phase-2 spec).

### Phase 5 — Docs

- `docs/guides/06-websockets.md`: STOMP section (quickstart, destinations
  vs rooms, receipts, ack modes, client usage), deferral note updated
  (drop STOMP from "not built"; keep SockJS never + cross-node pub/sub).
- `docs/plans/README.md` index entry (Active).
- `docs/decisions/README`-style ADR index if one exists (match AD-21/22
  treatment).

## 7. Non-goals / deferred (documented)

**Closed by the second wave (AD-23 D7–D11, 2026-09-16):**

- **STOMP transactions** (BEGIN/COMMIT/ABORT) — now brokered per-session
  (D7): buffered SEND/ACK/NACK + COMMIT/ABORT, receipts held to commit.
- **Binary frames/bodies** — now byte-exact (D8): codec accepts
  `string | Uint8Array | ArrayBuffer | Buffer`, emits `string | Uint8Array`;
  transport sends `Uint8Array`/`ArrayBuffer` as binary frames.
- **NACK redelivery** — now real, bounded (D9): per-subscription unacked
  tracking (`maxUnacked`), `redelivered: true` on NACK, cumulative
  `client`-mode acks.
- **`/user` destinations** — now principal-scoped (D10): `resolveUser`
  seam + `sendToUser`, Spring `/user/<suffix>` convention.
- **`/queue` destinations** — now bounded store-and-forward (D11):
  backlog replay to new subscribers (`queueBacklog`).

**Still deferred:**

- **Durable persistence behind `/queue`** — backlog is in-memory bounded
  (FIFO eviction); durable storage needs the audit's store contract
  (M4, post-1.0).
- **STOMP over TCP — never.** The 2026-09-16 review confirmed there is no
  consumer base for a raw TCP listener: browsers, STOMP.js, and Spring all
  speak the WebSocket variant. Like SockJS, it is not a gap, it is a
  non-feature.
- **SockJS — never** (AD-22 D4); **cross-node pub/sub** unchanged
  (post-1.0, needs a store contract).

## 8. Risks & open questions

| Risk                                                 | Mitigation                                                                                                                                                  |
| ---------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| First-frame-CONNECT race with reconnect client       | Client sends CONNECT on every `open` transition; server treats the socket as a fresh STOMP session per connection (it is — new `SocketSession` per upgrade) |
| Subscription streams vs reconnect gap                | Streams are reader-side (`AsyncReader`); frames only flow while connected; re-SUBSCRIBE restores routing, no republish (documented in-memory semantics)     |
| `handleProtocols` behavior change on non-stomp paths | Selection falls back to first-offered — identical to today's no-hook default (verified in `ws` source)                                                      |
| Escaping drift between 1.1/1.2 clients               | Parse tolerates both (decode 1.2 escape set; `:` never escaped pre-1.1 is a non-issue — values containing `:` are legal unescaped)                          |

Open: none blocking.
