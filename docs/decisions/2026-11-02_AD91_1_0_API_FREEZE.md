# AD-91: The 1.0 API freeze — reviewed surface and accepted shapes

**Date:** 2026-11-02
**Status:** Accepted
**Deciders:** Framework owner (2026-11-02 1.0-freeze validation review —
the closing record for AD-20 D8, whose naming review ran as AD-83)

---

## Context

AD-20 D8 parked "one deliberate naming review of the participatory decorator
family" before the 1.0 freeze. That review ran 2026-10-31 and became **AD-83**
(issue #8, closed): a role-keyed decorator taxonomy, three pre-1.0 renames
without aliases (`@generatedColumn`, `@sharedDependency`, `@nestedConfig`), and
the `@whenProfile` profile unification. `ARCHITECTURE.md` records the item as
completed.

AD-83's scope was the **decorator family**. Two other public shapes were
annotated "flag for the API-freeze review" in their plans while shipping, and
no record resolved them:

- **Account-epoch revocation** (`@ndigo/auth-server`) — the store contract
  requires a single atomic `UPDATE … SET token_version = token_version + 1`,
  described in its plan as "breaking-ish (pre-1.0, flagged for the API-freeze
  review; all implementers updated)" (`docs/plans/2026-09-26_AUTH_COMPLETION.md`).
- **`parseDerivedQuery`** (`@ndigo/orm-drizzle`) — reworked from the 1–2
  property regexes to a general grammar returning
  `DerivedQuery { filters, orderBy?, limit? }`, described as "a breaking change
  to the public `parseDerivedQuery` return type (pre-1.0, flag for the
  API-freeze review)" (`docs/plans/2026-09-26_ORM_COMPLETION.md`).

The release gate (#10) additionally needs a declared freeze surface: without
one, "1.0" is a version number rather than a promise.

## Decision

### D1 — The freeze surface is the public API at the release commit

"Frozen" means: exported symbols reachable from a package's `exports` map
(`src/index.ts` and declared subpaths), their type signatures, and their
documented behavior. Internal modules (`_*.ts`), `lib/`, and `api/` are not
part of the promise. Package-internal file layout is explicitly outside it.

### D2 — Accept account-epoch revocation as shipped

`token_version` (AD-68) is accepted as the revocation contract. It is
additive to the session model rather than a break of it — the "breaking-ish"
note tracked the implementer-facing change (every store must honor the epoch),
not a consumer-visible reshape. No alias or compatibility shim is owed.

### D3 — Accept the `DerivedQuery` return shape as shipped

`parseDerivedQuery` returning `DerivedQuery` is accepted. The alternative —
restoring the narrow regex result — would delete the general grammar the ORM
rows depend on (AD-30/31, `2026-09-26_ORM_COMPLETION.md`). Pre-1.0 was the
window for this change; the window closes here.

### D4 — No deprecation-alias debt at 1.0

The pre-1.0 renames (AD-83 decorators, AD-84's `@ndigo/util` surface prune)
landed as hard cuts with no aliases, deliberately: the repository has no
external consumers yet, so a shim would be permanent cost with no beneficiary.
1.0 therefore ships **without** a deprecation layer, and none is promised.

### D5 — Additive after 1.0; breaking waits, or hides behind a flag

Post-1.0 changes to the frozen surface are additive. A breaking change waits
for the next major or merges incomplete behind `@ndigo/flags` (the release
doctrine in `AGENTS.md` §8). Gated capability work that is still open — the
industry-gap register (GAP-9/10/14/16/17/18/19/20) and the ADR-recorded
deferrals with revisit triggers — is **not** part of this freeze: each lands
as its own decision when its trigger fires.

## Consequences

- The release gate (#10) has a defensible answer to "what is frozen?" — the
  `exports` map at the release commit, per D1.
- The two flagged plan annotations are resolved: the historical plans keep
  their text (records are historical), and this ADR is the resolution they
  point at.
- The freeze adds no code, no aliases, and no shims; the only cost is that
  breaking changes after 1.0 need a major or a flag.
- Naming continues under AD-83's taxonomy — a new decorator picks a category
  first, and deviations must land in AD-83.

## Revisit Trigger

Two, and only two:

- **A breaking change to the frozen surface is proposed.** The answer is
  already decided (D5): the next major, or a flag. Re-open this record only if
  the flag route proves unworkable in practice.
- **The first external consumer appears.** D4's no-alias position rests on the
  repository having no consumers; a real one is the condition under which the
  cost of a deprecation layer deserves re-weighing — for the _following_
  release, not retroactively for 1.0.
