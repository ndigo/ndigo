# 2026-03-30 ORM MVP

## Objective

Introduce `@blue/orm` as a Layer 2 (Infrastructure) package providing Repository + Data Mapper persistence abstractions with an in-memory adapter for immediate use in `blue-demo`.

## Design Decisions

| Decision            | Choice                             | Rationale                                                                         |
| :------------------ | :--------------------------------- | :-------------------------------------------------------------------------------- |
| Platform            | Universal (isomorphic core)        | Matches BlueJS's portability vision                                               |
| MVP scope           | Contracts + in-memory adapter      | Usable in blue-demo immediately, no external deps                                 |
| Wrap vs. build      | Pure contracts for MVP, wrap later | Keeps core dependency-free; adapter packages later                                |
| Pattern             | Repository + Data Mapper           | Aligns with Spring Data JPA, fits existing DI/IoC                                 |
| Layer placement     | Layer 2 (Infrastructure)           | Alongside `@blue/factory`, `@blue/validate`                                       |
| Context integration | Via existing protocols             | `Initializable`/`Destroyable` from `@blue/factory`; no `@blue/context` dependency |

## Dependencies

- `@blue/core` (L1) — errors, primitives, `Constructable`
- `@blue/factory` (L2) — `Initializable`, `Destroyable`, `ContextToken`
- NO dependency on `@blue/context` (L3)

## Core API Surface

### Decorators (all camelCase per STYLE_GUIDE.md)

- `@entity(tableName?)` — marks a class as a persistent entity
- `@primaryColumn()` — marks the primary key field
- `@column(options?)` — marks a field as a persisted column
- `@generated()` — auto-generated value (for IDs)

### Interfaces

- `DataSource` — connection/store abstraction (`Initializable`, `Destroyable`)
- `EntityManager` — persistence operations (`persist`, `find`, `findAll`, `remove`, `flush`)
- `Repository<T, ID>` — collection-like interface (`save`, `findById`, `findAll`, `deleteById`, `count`)
- `UnitOfWork` — tracks entity states (new/dirty/removed), provides `flush()`

### In-Memory Implementations

- `InMemoryDataSource` — `Map`-based store, keyed by entity type
- `InMemoryEntityManager` — implements `EntityManager` over `InMemoryDataSource`
- `InMemoryRepository<T, ID>` — concrete `Repository` using `InMemoryEntityManager`
- `InMemoryUnitOfWork` — tracks entity states in memory, delegates flush to `EntityManager`

## Context Integration Pattern

ORM beans integrate with `@blue/context` via existing protocols — no coupling required:

```typescript
// In a @configuration class:
@entry()
dataSource() {
    return new InMemoryDataSource();
}

@entry()
todoRepository() {
    return new InMemoryRepository(Todo, this.dataSource());
}
```

The `ApplicationContextAwareProcessor` in `@blue/context` automatically calls `init()` on beans implementing `Initializable` and `destroy()` on beans implementing `Destroyable`.

## Deferred to Post-MVP

- Relation decorators (`@oneToMany`, `@manyToOne`, etc.)
- Query builder / query derivation
- Entity lifecycle hooks (`@prePersist`, `@postLoad`, etc.)
- `@transactional` decorator
- Migrations
- Real database adapters (`@blue/orm-drizzle`, `@blue/orm-mikro`)
- `@blue/validate` integration for entity validation

## Success Criteria

- All decorators store metadata correctly in `Symbol.metadata`
- `InMemoryDataSource` passes CRUD lifecycle tests
- `InMemoryEntityManager` supports persist/find/findAll/remove/flush
- `InMemoryRepository` provides collection-like API over EntityManager
- `InMemoryUnitOfWork` tracks entity states and flushes correctly
- Package builds cleanly (`pnpm build`)
- All tests pass (`pnpm test`)
- Lint passes (`pnpm lint`)
- No direct imports from encapsulated libraries

## Risks

- Metadata key collisions with other decorator packages (mitigated by `orm:` prefix)
- Over-engineering the in-memory adapter (mitigated by strict MVP scope)
- API surface may need revision when real adapters are added (accepted — MVP is contracts-first)
